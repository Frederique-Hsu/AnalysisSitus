Build on Linux

Getting ready

This guide is a step-by-step tutorial explaining how to build Analysis Situs from sources on Linux OS. Ubuntu 22.04 and Fedora 42 are used throughout this guide, although the compilation process should be similar for other Linux distros. It should be noted that Analysis Situs is a C++-written project whose language support is deliberately narrowed down to C++11 standard for the sake of better compatibility with older compilers.

Analysis Situs is entirely free and can be compiled without any commercial products or 3-rd parties. Still, for comfortable development under Linux OS, the authors of Analysis Situs recommend using the following proprietary software (although you may freely choose the free alternatives to the packages listed below):

  1. GitKraken as a git client.
  2. CLion as a C++ IDE.

None of these commercial tools are required to build Analysis Situs. We only recommend using them for the development and maintenance although you might also prefer VS Code or any other IDEs and tools by your choice.

The compilation procedure given below assumes that you have a "clean" installation of Linux. As a result, it goes through all of the steps to install the required third-party dependencies, some of which your system may already have installed. If this is the case, you may skip the corresponding steps. Also, keep in mind that Analysis Situs is a rapidly evolving project. Although we try to minimize the dependencies and keep the compilation process as clean as possible, some inconsistencies may pop up. Please, report, if you encounter any.

Install development tools

CMake

Analysis Situs is configured with CMake. To install CMake, you go like this:

Ubuntu 
sudo apt install cmake-qt-gui
Fedora 
sudo dnf install cmake
sudo dnf install cmake-gui.x86_64

To make sure that CMake is installed properly, run it like this from the Terminal: 

cmake-gui&

You should be able to see the CMake window:

It is recommended to try to configure the project for the first time to observe all missing dependencies. To do that, you have to input the source and the build directories, then press "Configure" and choose "Unix Makefiles" as the generator:

On a clean installation, you might also need to install the compiler.

Fedora 
sudo dnf install gcc-c++.x86_64

If this is not done, CMake may claim that it cannot recognize the language: 

CMake Error at CMakeLists.txt:39 (project):
  No CMAKE_C_COMPILER could be found.

  Tell CMake where to find the compiler by setting either the environment
  variable "CC" or the CMake cache entry CMAKE_C_COMPILER to the full path to
  the compiler, or to the compiler name if it is in the PATH.


CMake Error at CMakeLists.txt:39 (project):
  No CMAKE_CXX_COMPILER could be found.

  Tell CMake where to find the compiler by setting either the environment
  variable "CXX" or the CMake cache entry CMAKE_CXX_COMPILER to the full path
  to the compiler, or to the compiler name if it is in the PATH.

The next stage is to specify "/usr/lib" as the value of "3RDPARTY_DIR" and set "INSTALL_DIR" to the directory where Analysis Situs will be copied upon successful compilation. Also, specify "Release" as "CMAKE_BUILD_TYPE" to compile the project in the optimized mode (for debugging, you may want to type "Debug").

Keep the CMake GUI dialog open and proceed with installation of other 3-rd party libraries following this guide.

It should be noted that on Linux systems, the "/usr/lib" path is used as a default value for the "3RDPARTY_DIR" CMake variable.

Rapidjson

Analysis Situs provides a comprehensive framework for feature recognition. To output the recognition results in a persistent way, it uses JSON format. At the level of C++, JSON documents are manipulated with Rapidjson library. To install Rapidjson, use the following command:

Ubuntu 
sudo apt-get -y install rapidjson-dev
Fedora 
sudo dnf install rapidjson-devel.x86_64

Rapidjson is a header-only library, so we do not need to configure the linker and install any binaries.

Eigen

Eigen is a header-only library for linear algebra. Install the development version as follows:

Ubuntu 
sudo apt-get -y install libeigen3-dev
Fedora 
sudo dnf install eigen3-devel

OpenCascade dependencies

Tcl/Tk and freeimage are the dependencies of OpenCascade. Install with:

Ubuntu 
sudo apt-get install -y tcl tcl-dev tk tk-dev libfreeimage-dev
Fedora 
sudo dnf install tcl-devel.x86_64
sudo dnf install tk-devel.x86_64
sudo dnf install freeimage-devel.x86_64

OpenGL

More dependencies for graphics are to be installed in the following way:

Ubuntu 
sudo apt-get install -y libxmu-dev libxi-dev
sudo apt-get install -y libglfw3-dev libgl1-mesa-dev libglu1-mesa-dev libosmesa6-dev
Fedora 
sudo dnf install mesa-libGL-devel.x86_64

Without MESA driver available, an attempt to build OpenCascade may result in the following error: 

...OpenGl_GlFunctions.hxx:65:12: fatal error: GL/gl.h: No such file or directory
   65 |   #include <GL/gl.h>

OpenCascade

Analysis Situs uses a fork of OpenCascade 7.6 as a geometric kernel. We prefer to build OpenCascade from sources. To do so, execute the following commands one after another (make sure to set your working directory properly): 

mkdir /home/quaoar/work/opencascade
cd /home/quaoar/work/opencascade
git clone https://gitlab.com/ssv/opencascade-analysis-situs.git ./
mkdir ./build
cd ./build
cmake .. \
    -DCMAKE_BUILD_TYPE=release \
    -DCMAKE_INSTALL_PREFIX=/usr \
    -DUSE_FREEIMAGE=ON \
    -DUSE_FREETYPE=ON
make -j8
sudo make install

It should be noted that here we install OpenCascade into the system directory "/usr". That is why you would need administrative permissions for "make install".

At this point, it might be interesting to check that OpenCascade has been installed successfully by giving it a test run. For that, you can go like this: 

cd /usr/bin
./draw.sh

In the launched DRAW session, give the following commands: 

pload ALL
box a 0 0 0 1 1 1
vinit
display a
vfit

It should be noted that on Linux, OpenCascade uses MESA (i.e. software rendering), so you should be able to work with 3D graphics even without video drivers preinstalled.

Qt

Qt is the UI framework used by Analysis Situs. Install it with the following commands:

Ubuntu 
sudo apt-get update
sudo apt-get -y install libqt5x11extras5-dev
sudo apt-get -y install qttools5-dev
Fedora 
sudo dnf install qt5-qttools-devel.x86_64
sudo dnf install libXt-devel.x86_64
sudo dnf install qt5-qtx11extras-devel

Notice that we also install "X11 Extras" and "X11_Xt_LIB" packages. If they are missing, you will have problems at VTK configuration stage.

VTK (fork)

The visualization module of Analysis Situs is based entirely on VTK framework. Unlike Qt, here it is necessary to have a specific version of the library, which is the patched ver.8.2 in our case. We prefer to build VTK from sources. To do that, use the following commands: 

cd /home/quaoar/work
mkdir ./vtk
cd ./vtk
git clone https://gitlab.com/ssv/vtk-analysis-situs.git ./
mkdir ./build
cd ./build
cmake .. \
    -DVTK_Group_Qt=ON \
    -DVTK_QT_VERSION=5 \
    -DVTK_RENDERING_BACKEND=OpenGL2 \
    -DVTK_Group_Imaging=YES \
    -DVTK_Group_Qt=YES \
    -DVTK_Group_Views=YES \
    -DVTK_REPORT_OPENGL_ERRORS=NO \
    -DBUILD_SHARED_LIBS=ON \
    -DVTK_USE_SYSTEM_LIBXML2=ON \
    -DVTK_USE_SYSTEM_EIGEN=ON\
    -DCMAKE_BUILD_TYPE=Release \
    -DCMAKE_INSTALL_PREFIX=/usr
make -j8
sudo make install

It might happen that you encounter compilation or linking problems if using the official VTK-8.2 package from Kitware. The ver.8.2 of VTK is already quite obsolete, while gcc compiler, Qt and potentially something else in your Linux environment keeps evolving. For example, VTK-8.2 would not see any compilation issues on Ubuntu 20.04, while on Ubuntu 22.04 the situation becomes worse. Ideally, Analysis Situs should be migrated to a newer version of VTK, but that was hardly possible last time we tried it.

It should be noted that VTK comes with a set of bundled 3-rd party libraries. These libraries are being compiled from sources, but, with the changes in Linux kernel and newer versions of gcc, the bundled sources may get outdated. We therefore recommend building VTK against system libraries (libXml2 and Eigen), which is indicated by enabling the corresponding CMake flags "VTK_USE_SYSTEM_LIBXML2" and "VTK_USE_SYSTEM_EIGEN" above.

For debug builds, it is useful to disable OpenGL "state checks" provided by VTK. These checks may sometimes fail and lead to reporting of verbose diagnostics, e.g., when imperative viewer is used in the code.

VTK (official)

With some adjustments and limitations, Analysis Situs UI can be backed by more modern versions of the VTK library. If you'd like to use the official release of VTK (such as ver.9.5), you may compile it from sources using the following commands: 

cd /home/quaoar/work
mkdir ./vtk
cd ./vtk
git clone https://gitlab.kitware.com/vtk/vtk.git ./
git checkout v9.5.0.rc1
mkdir ./build
cd ./build
cmake .. \
    -DVTK_GROUP_ENABLE_Qt=YES \
    -DVTK_QT_VERSION=5 \
    -DVTK_MODULE_ENABLE_VTK_GUISupportQtQuick=NO \
    -DVTK_REPORT_OPENGL_ERRORS=NO \
    -DBUILD_SHARED_LIBS=ON \
    -DCMAKE_BUILD_TYPE=Release \
    -DCMAKE_INSTALL_PREFIX=/usr
make -j8
sudo make install

Generate Makefiles

At this point you can try reconfiguring Analysis Situs in CMake:

Alternatively, you may want to configure and build Analysis Situs entirely from the terminal: 

cd /home/quaoar/work
mkdir ./analysissitus
cd ./analysissitus/
git clone https://gitlab.com/ssv/AnalysisSitus.git ./
mkdir ./build
cd ./build
cmake .. \
 -DCMAKE_BUILD_TYPE=Release \
 -D3RDPARTY_vtk_LIBRARY_DIR=/usr/lib64/ \
 -D3RDPARTY_vtk_INCLUDE_DIR=/usr/include/vtk-9.5 \
 -DINSTALL_DIR=/usr/local/bin/analysissitus
make -j8
sudo make install

To run Analysis Situs, navigate to the installation directory and run its bash executable like this: 

./asiExe.sh

To test if Analysis Situs is operational, consider executing the following commands in the "Active Script" console: 

make-box a 0 0 0 1 1 1
set-as-part a

Pay attention to the visualization of edges. If your video-driver is fine, you should be able to see them.

Dockerfile

The procedure detailed above is automated in the Dockerfile available in your working copy of Analysis Situs. Therefore, you may prefer to build Analysis Situs with UI in a Docker container.
