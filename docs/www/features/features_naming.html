Topology naming service

During model editing in Analysis Situs, you may need to ensure that the CAD face IDs remain intact. This is not the case with serial face IDs, which correspond to the order of topology graph visits. For attaching "stronger" IDs with CAD faces, one approach is to use the inline naming service. The following animation demonstrates how defeaturing works without the naming service enabled (pay attention to what happens to face indices):

The naming service is a wrapper for modification history recorded in the Part Node. This service is valid for a single application run, and the history is lost when a Part is reinitialized (for example, reloaded from a file). With the naming service enabled, you can keep track of faces by their associated names instead of using the volatile indices:

With the naming service turned on, faces are updated from the stored history graph and inherit the names of their preimages. This allows you to continue working on the updated model while retaining the previously initialized face names. Use the init-naming command to initialize the naming service for the active part.

To validate if naming service contains a history graph consistent with the present state of boundary representation, you may want to consult the dedicated graph view. The view is enabled as follows (in C++): 

// History from the Part Node.
Handle(asiAlgo_History) history = ...;

// Visualize history in graph view
asiUI_HistoryGraph*
  pGraph = new asiUI_HistoryGraph( model,
                                   history,
                                   progress,
                                   plotter );
//
pGraph->Render();

Using the graph view, you can check if the evolved boundary elements are "alive" in the present state of the model. It may happen that the history of modification does not contain "alive" entities in the cases when the history chain is broken. This situation normally indicates a logical flaw in one of the employed modeling algorithms.

A practical way to see if naming service works for a specific algorithm is enabling it, performing the shape modification of interest and consulting the history wrapped by the naming service. If all goes well, the evolution traces for the boundary elements should end with "alive" (green) nodes. Clicking on the associated graph nodes displays the corresponding B-rep entity in the viewer (even if it is not "alive").

Use the get-face-name function to access the face name by its serial ID from the initialized naming service. Use the get-face-id or get-face-ids function to access the serial face IDs by their names.
