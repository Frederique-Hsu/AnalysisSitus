Ver. 2025.1

This page describes the functional changes made to the Analysis Situs Commercial SDK in version 2025.1. The first section provides highlights of the most essential features and fixes. The remainder of this page is devoted to the changelog, which contains a list of all commits as well as pointers to the associated private tickets. If you inquired about improvements or bug fixes in the commercial SDK and were given a ticket number to reference, you should look up the ticket number in the changelog.

If you are using open-sourced SDK, check out the corresponding release notes here: "Analysis Situs 2025.1 is out."

SMRU, DXF

Bent pipes

In the new release of SMRU, bent pipes recognition has been introduced. The following table summarizes the new part types added to the recognition framework. For all types, common features are recognized, including sheet faces, thickness faces and cutouts. The global geometric properties, such as material thickness and pipe length are also extracted.

For round and rectangular tubes, the algorithm extracts medial axis with a specialized Medial Axis Transform (MAT) algorithm. The extracted axis is used to identify cutouts and some geometric properties of a bent part.

BENT_TUBE_ROUND

Bent round tubes are thin profiles swept along a spatial path. They are normally composed of straight segments connected with round folds. For this type of geometry a medial axis path is automatically extracted.

BENT_TUBE_RECTANGULAR

Bent rectangular tubes resemble normal rectangular tubes: they have a four-sided profile and contain rounded fillet-like corners. For this type of geometry a medial axis path is automatically extracted.

BENT_WIRE

Bent wires are non-hollow objects swept along a spatial path.

WIRE

Wires are plain cylindrical non-hollow objects.

If bent pipe recognition is enabled, the recognizer operates in normal mode and then attempts to recognize a part as a bent pipe if the default recognition attempts fail.

Contacting solids

For sheet metal structures, it is often required to propose welding as a final process. The prototype approach for identification of weldings was put together in the end of 2022 for automatic identification of weld pathways similarly to Verbotics Weld. Back then, we conducted a thorough R&D project and designed two algorithms that form the basis of the entire approach:

  • Fast distance measurement for detecting close solids.
  • Imprinting operator for solid intersection.

We devoted a technical article to explain different approaches to welding identification: "To automatic identification of welding joints in CAD assemblies." The reported contact zones between solids are dumped to glTF format. Their corresponding lengths are reported in the outcome JSON file.

Revamped DXF with layers

The Commercial SDK started off with an open-sourced DXF translator that has been used for quite some years. It was discovered that this translator has critical limitations, e.g., it does not allow to configure linetypes or layers easily. An alternative option was to use a commercial DXF translator shipped by a 3-rd party vendor (read "OpenCascade's XDE for DXF drawing generator" for details).

The 3-rd party option requires a separate license and has limited flexibility for customization. Therefore, we started an R&D project to revamp the open-sourced solution and make it more functionally rich. The new DXF translator has the capacity of maintaining separate layers. In ver.2025.1, this new capacity is used to report bend lines on top of the cutting contours.

In the future versions of SMRU, we are planning to employ layers further and report more features in the flat pattern drawings, e.g., center marks for holes.

Properties of drilled holes

The drilled holes contained in a sheet metal part are sometimes used for mounting additional accessoires, e.g., studs, bolts, brackets, etc. To have anchor positions for such extra mounting, we added hole center points and axes to the outcome of SMRU.

The reported axes are consistent along a sheet metal side, so you may always flip the mounting direction globally.

Cutting contour segments

SMRU reports cutting length for all contours, including the outer perimeters and cutouts. It may happen that single cutting length is not enough and you need more factorized information about the cutting contours to assess machining time. For segment extraction, SMRU decomposes each contour into its elementary primitives, such as straight line segments and arcs.

In the new release, the algorithm of segments extraction has been redesigned to provide stable output with consistent information about convexity of connection points. You may want to read more about this algorithm on our blog: "Segments over a planar contour."

Bending simulation preview

To assess feasibility of a sheet metal part with respect to the available punch tools, SMRU now contains a brand new simulation algorithm. You may want to read the detailed documentation on this utility here.

The only outcome of the algorithm in ver.2025.1 is the detected bending sequence or a warning code if such a sequence could not be found by the employed heuristic procedure. The warning code means that part looks tricky (if not infeasible) and might require special treatment for production. The simulation result is dumped in the outcome JSON in a separate block: 

"simulation": {
  "processingTime": 0.3652185999089852,
  "bendSequence": [[2], [1, 3]]
}

The bendSequence array reports bend IDs grouped in the "reversed time" mode, i.e., from the folded state down to the flat pattern. In the example above, the reported sequence means that the bend n.2 needs to be done before bends n.1 and n.3, although the order of bending within the latter group [1, 3] is not specifically checked.

The simulation algorithm is data-driven. You are allowed to define your own punches as two-dimensional geometric profiles that will be automatically loaded by the algorithm in the beginning of the simulation process. If no custom punches are provided, the algorithm will use its default tools that are good enough for a "glance" feasibility check. You may want to read more about the algorithm on our blog here: "On sheet metal unfolding. Part 12: searching for feasible bends."

CNC

Negative cells in glTF

The feature recognition algorithm for turned and turned+milled parts is capable of extracting negative volume cells for steps, grooves, and central holes. These cells are two-dimensional profiles whose geometry can be used to predict the required tools and their properties.

In the version 2025.1, it is now possible to have these profiles dumped in the glTF format. The exported meshes are grouped by the corresponding cell type.

Milling outlines

The open-source framework of Analysis Situs has got a new Outliner algorithm that allows to project parts and features onto the given reference plane. The algorithm is based on HLR and therefore works in two modes: precise (with analytical projection curves) and discrete (with polygonal output). The following image demonstrates an outline contour constructed for a milling pocket:

It is easy to see that the original pocket feature does not contain this contour among its own edges inherently, i.e., the outline can only be synthetized by projection. The projected outline can be used for machining time estimation directly or in the derived algorithms (such as delta volume construction).

ALM

Summary information

The preparation of parts to 3D printing starts with extracting global properties, such as mass-inertia characteristics of the shape, its bounding dimensions, searching for inner voids, etc. This information can now be summarized with the help of ALM (Additive Layered Manufacturing) component of the Commercial SDK. 

{
  "file": "C:/work/AnalysisSitus_EXT/data/alm/blade.obj-out.stl",
  "summary": {
    "bboxDx": 53.695399999999999,
    "bboxDy": 100.07990000000001,
    "bboxDz": 62.808499999999995,
    "totalFaceArea": 12041.584542061917,
    "totalVolume": 39890.806708305863,
    "numConnectedComponents": 1
  }
}

Besides this pure geometric data, other demanded artifacts include PNG preview images and surface triangulations in glTF format.

The ALM module works with mesh-based formats (such as STL) as well as with precise CAD formats (such as STEP). For precise B-rep, the ALM module automatically generates dense meshes that can be used not only for visualization but also for DFM analysis.

Common

WebGL feature-aware viewer

With the new release, our customers get access to Three.js-based web visualization component. This viewer imports the outcome glTF/JSON files generated by the feature recognizers and provides basic interaction, such as face selection and manipulations with camera. The geometric properties of the selected features are extracted from the corresponding JSON data. You may want to read our dedicated announcement regarding this new component: "Feature recognition on the web."

We deliver our web viewer in sources and invite our customers to use it as a guidline example for their own development. The web viewer demonstrates how CAD data is communicated between the frontend GUI and the artifact files (JSON, glTF, PNG, etc.) generated by a server.
