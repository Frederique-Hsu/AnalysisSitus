WIP (unscheduled)

The task list below represents our "dynamic" roadmap for the Extensions SDK. Looking at it will give you a better sense of the features, upgrades, and bug fixes that we are currently working on. Typically, not all of the items listed below will make it into the future release of the SDK. Still, you can see what's around the corner not waiting for the official releases.

  • [Nesting] #1054: BLF-based 2D nesting.
  • [Simplification] Introduce simplification SDK.
  • [SMRU] Report face IDs of the base faces a hole belongs to.
  • [SMRU] Incremental mode of bending sequence simulation if bend groups cannot be unfolded.
  • [SMRU] #1091: Propagate part names on compound expansion in the format "partName x/y".
  • [SMRU] Feature recognition on named B-rep entities.
  • [SMRU] Instability of test cases on Linux.
  • [SMRU] CI/CD for linux builds.
  • [SMRU] Advanced algorithm for laser-cut parts having machining features.
  • [SMRU] #1060: Face IDs of the closest cutout are demanded for better DFM reporting.
  • [SMRU] #1034: Compute and report the convex hull of a flat pattern.
  • [ALM] Add thickness analysis as an option for 3D printing toolbox.
  • [SMRU] #1069: Holes that have full-depth countersinks not having a correct hole location.
  • [SMRU] #1070: An inconsistent assembly item ID is reported for a welding candidate component.
  • [SMRU] #1072: Flat hem detection affects extreme cases only.
  • [CNC] Introduce strategies for negative volumes: off, regular polygons, raw prisms, normalized point clouds.

SMRU, DXF

  • [SMRU] #1082: Report thickness faces in a separate plain array named `thicknessFaceIds`.
  • [SMRU] #1081: Some U-type profiles with uneven thickness are misrecognized as folded sheet metal parts.
  • [SMRU] #1078: Assemblies are restored from the scene tree with misplaced part occurrences.
  • [SMRU] DXF file generated by SMRU for a flat shape looks wrong (misplaced holes).
  • [SMRU] #1068: Engravings are sometimes not detected on linux (docker).
  • [SMRU] Introduce welding spots detection prototype.
  • [SMRU] #619: Make automatic welding identification between assembly components an optional mode of SMRU.
  • [SMRU] #619: Dump glTF files for welding pathways.
  • [SMRU] #1050: Refer to a part ID from a welding candidate object reported in JSON.
  • [SMRU] #744: Introduce bent pipes recognition.
  • [SMRU] Rename props for bent pipes and update reference data.
  • [SMRU] Recognize straight wires.
  • [DXF] Revamp DXF writer to support layers.
  • [SMRU, DXF] Report bend lines as a separate layer in SMRU.
  • [SMRU] Fix #1035: Save thick solid of the flat shape as a STEP file.
  • [SMRU] Fix #1038: SVG export is unreasonably slow (make SVG export orders of magnitude faster).
  • [SMRU] Fix #1046: glTF meshes are not located optimally.
  • [DXF] #640: `dxf-perform` hangs on the provided part.
  • [SMRU] Fix #1036: Calibrate meshing parameters for dumping artifacts.
  • [SMRU] Fix #1050: Remove prototype IDs from the `assemblyItemId` paths in the instance objects reported in a Scene Tree.
  • [SMRU] Fix #1033: Add information about center points halfway between the two faces and axes for holes.
  • [SMRU] #1049: Report distances between parallel bend lines.
  • [SMRU] #1055: The `hasSupportEdge` property should only account for the straight edges that are parallel to the bend lines.
  • [SMRU] Fix #992: Bounding box of a flat part is suboptimal: use optimization of flat projections if the longer straight edges are shorter than 40% of the bbox max side.
  • [SMRU] Fix #1062: Report hole locations with the automatically applied optimal transformation in the glTF file.
  • [SMRU] #1075: Layers in the DXF files exported by SMRU should be optional.
  • [SMRU] #1047: Make segments reporting more consistent in the convention over the reported angles.
  • [SMRU] Introduce bending simulation prototype.
  • [SMRU] Introduce `sm-unfold` interactive command with unfolding tree visualization.
  • [SMRU] #1092: Automatically reorient unrecognized parts.

CNC

  • [CNC] Dump turning profile and negative cells to glTF.

Nesting

  • [Nesting] #927: Introduce 3D nesting algorithm based on DBLF placement rule and AABB-based collision checker.
  • [Nesting] #1064: Incremental adding of 3D nesting containers.
  • [Nesting] Transform bbox of a part on placement to correctly compute z-height.
  • [Nesting] #1076: Do not let the 3D-nested parts hang over the container's dimensions.

ALM

  • [ALM] Fix #1067: glTF meshes from 3D printing summary extraction come in "black".
  • [ALM] #1071: The normals in the GLB output reported by 3D printing detection are all in Y direction.

Common
