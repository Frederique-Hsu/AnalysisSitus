3D packing overview

Input

3D nesting reads its inputs from a JSON file. One example of an input is given below. 

{
  "outputDir": "./out",
  "container": {
    "name": "c",
    "xDim": 400,
    "yDim": 300,
    "zDim": 200,
    "cellSize": 10
  },
  "settings": {
    "enablePartDecimation": true
  },
  "parts": [
    {
      "filename": "alm/blade.obj-out.stl",
      "count": 6
    },
    {
      "filename": "alm/armchair.obj-out.stl",
      "count": 5
    }
  ]
}

The input JSON declares the container's properties, algorithm parameters, and part descriptions. The information stored in the container and parts sections turns into the so-called "prototype" objects by the algorithm. Each container's prototype may create many container objects where nesting will occur. The count attribute specifies how many instances of each part are generated by the prototype.

Draw attention to the numUnnestableParts JSON property. It counts how many parts (prototypes) cannot be nested because their dimensions do not fit into the specified container size.

Perform nesting

To perform 3D nesting from the command prompt of Analysis Situs, use the nesting-perform command followed by the filename of the input file: 

> nesting-perform -filename {data}/input.json

The algorithm will do the job and open up the UI dialog with the nesting summary. The nested parts are rendered in the incrementally added containers. The output directory for the generated artifacts (JSON, STL) is specified in the input JSON file. To override the output directory in the script, use the optional -outdir argument followed by the target path. 

> nesting-perform -filename {data}/input.json -outdir {desktop}

To run 3D nesting in the batch mode, use asiNestingExe executable followed by the path to the JSON input file.

3D nesting adds containers incrementally. For example, if the next part cannot be placed in the current container, it is tagged as "pending" and skipped along with all of its instances. The algorithm continues with other parts, checking if the existing container may still be utilized for accommodating smaller parts. Upon completion, a new container is allocated and all "pending" parts are reiterated.

The algorithm does not really shift containers with respect to one another when it performs packing. However, for visual study, the allocated containers are arranged in "lexicographical" order, allowing the user to look closer at the nesting results. It should be noted that rendering large numbers of meshes can be memory intensive. To deal with this, consider passing the -drawOpt key to the algorithm. This mode renders optimized (decimated) versions of parts.
