3D printing summary

The abbreviation ALM stands for "Additive Layered Manufacturing." In the Analysis Situs SDK, this term refers to all 3D printing methods, including FDM, SLS, MJF, and other production types. From a geometric perspective, 3D printing processes require specific data preparation workflows. Still, regardless of the fabrication method, there is a common API to extract summary information such as part volume, surface area, bounding box dimensions, and so on. An example of these summary properties collected by the ALM SDK is given below. 

{
  "file": "Rocker Arm_input.stl",
  "summary": {
    "bboxDx": 0.30336600542068481,
    "bboxDy": 0.51445502042770386,
    "bboxDz": 0.99943101406097412,
    "totalFaceArea": 1.2913252120115157,
    "totalVolume": 0.042490076845111052,
    "numConnectedComponents": 1
  }
}

The alm-perform command can be used in the Active Script session to perform summary extraction for a 3D printed part. The accepted formats are mesh (STL) and B-rep (STEP). The same logic can be used from within C++ and asiAlmExe executable. The following script illustrates a typical way of running the ALM recognition workflow: 

> clear; alm-perform -filename mesh.stl

Aside from the JSON summary, the ALM SDK translates the input to glTF format for display in the client's application.

To apply proper lightning, many viewers require a normal field associated with the mesh triangles. Analysis Situs calculates mesh normals per facet and exports them as glTF along with the meshes. Often, 3D viewers average normals at vertices, resulting in "puffy" renders. If it is not what you want, you can use your viewer's "flat shading" mode (click image below to enlarge).

The SDK also generates a PNG thumbnail ("preview") image.

The meshes imported by the SDK from the STL files are passed through processing as they are. If a STEP file is loaded, the underlying B-rep is first tessellated by our uniform quadtree-based faceter to generate dense meshes.
