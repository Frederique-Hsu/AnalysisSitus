3D packing

DBLF algorithm

A part occurrence $S$ that is nested stores the last nested location for the entire family of the same parts. This allows the family to bypass previously examined spots, which is one of the simplest optimization approaches used. The pseudocode below illustrates a simple logic for DBLF in which parts cannot freely rotate.

In the algorithm, all grid points are numbered in the order of DBLF visiting. Therefore, each grid point has two addresses: the serial index $r$ and the coordinates $i,j,k$. 

  % DBLF packing algorithm (www.analysissitus.org).
  \begin{algorithm}
  \caption{Deepest-Bottom-Left-Fill (DBLF)}
  \begin{algorithmic}
  \PROCEDURE{DBLF}{$S, C$}
    \STATE \Comment{$S$ is a part to nest.}
    \STATE \Comment{$C$ is a target container.}
    \STATE \CALL{ComputePointPattern}{$S$} \Comment{Prepare point pattern for the solid $S$.}
    \STATE \CALL{ComputeBBox}{$S$} \Comment{Compute AABB of the part.}
    \STATE \CALL{ComputeAnchorPoint}{$S$} \Comment{Compute anchor point of the part.}
    \STATE \CALL{Unlock}{$C$} \Comment{Unlock all grid points in the container.}
    \STATE stop $\gets$ false
    \STATE nested $\gets$ false
    \STATE $M$ $\gets$ \CALL{GetNumOfPoints}{$C$} \Comment{Number of grid points in the container.}
    \REPEAT
      \STATE $G_{r}$ $\gets$ -1 \Comment{Next placement to try (serial index).}
      \STATE $G_{i,j,k}$ $\gets$ $\{-1,-1,-1\}$ \Comment{Next placement to try (triplet).}
      \STATE $P_s$ $\gets$ \CALL{LastNestedPos}{$S$} \Comment{Get the last nested position's index of the $S$ family.}
      \FOR{$r \in [P_s,M)$}
        \STATE $P$ $\gets$ $C[r]$
        \IF{$P$ is not occupied and not locked}
          \STATE $G_{r}$ $\gets$ $r$
          \STATE $G_{i,j,k}$ $\gets$ \CALL{FromPlain}{$r$, $C$} \Comment{Turn serial index $r$ to triplet $i,j,k$.}
          \BREAK
        \ENDIF
      \ENDFOR
      \IF{$G_{r}$ = -1} \Comment{No position to try.}
        \STATE stop $\gets$ true
        \CONTINUE
      \ENDIF
      \STATE $C[G_{r}]$.locked $= true$ \Comment{Lock current snapping point.}
      \STATE $N \gets$ \CALL{GetNeighborhood}{$G_{r}$}
      \STATE $N$.isRoomy $\gets$ \CALL{IsCursorPromising}{$N$, $S$}
      \IF{ !$N$.isRoomy }
        \CONTINUE
      \ENDIF
      \STATE \CALL{MovePart}{$S$, $C[G_{r}]$} \Comment{Snap anchor point to the grid point.}
      \IF{ \CALL{HaveCollisions}{$S$, $C$} }
      \STATE \CALL{SetLastNestedPos}{$S$, $G_{i,j,k}$} \Comment{Continue from here.}
        \CONTINUE
      \ENDIF
      \STATE $R \gets$ \CALL{GetSpannedPoints}{$S$} \Comment{Find grid points enclosed by the moved part.}
      \STATE \CALL{SetOccupied}{$R$} \Comment{All spanned point become occupied.}
      \STATE \CALL{SetLastNestedPos}{$S$, $G_{i,j,k}$}
      \STATE stop $\gets$ true
      \STATE nested $\gets$ true
    \UNTIL{ !stop }
    \RETURN nested
  \ENDPROCEDURE
  \end{algorithmic}
  \end{algorithm}

The algorithm first finds the next vacant position $G_r \equiv G_{i,j,k}$ and analyzes its neighborhood $N$. If the neighborhood is "roomy" enough, then the candidate part is moved to this vacant position and collisions are tested. If no collisions are found, the points enclosed by the part are marked as "occupied," and the process finishes. If there are collisions, then the process continues, given that the current point is temporarily "locked," so it will not be visited again.
